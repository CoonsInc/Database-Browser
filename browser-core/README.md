# browser-core

Java 17, обычный Gradle java-library; runtime-зависимостей нет. JUnit Jupiter 6
используется только в тестах. Из корня репозитория: `./gradlew :browser-core:build`.
SQLite JDBC используется в модуле `browser-sqlite`.

## Публичный API

Пакет `org.databasebrowser.core`:

- `domain`: группы публичных типов `Ids`, `Errors`, `Connections`, `Schema`,
  `Changes`, `Sql`, `QueryPlans`, `Exports`. Вложенные records импортируются, например: `org.databasebrowser.core.domain.Schema.Table`.
- `application`: `ChangeValidator`, `CsvService`.
- `application.session`: открытие, состояние и закрытие сессий.
- `application.sql`: выполнение SQL, отмена и курсоры.
- `application.schema`: чтение схемы, применение изменений и экспорт DDL.
- `port`: `AdapterProvider` и девять обязательных портов: `ConnectionPort`,
  `DatabaseInfoPort`, `SchemaReaderPort`, `SchemaChangePort`, `SqlExecutionPort`,
  `QueryPlanPort`, `DdlExportPort`, `TextFilePort`, `CsvExportPort`.

Приложение создаёт один `SessionRegistry` на все сервисы. Экран подключений получает
его как `ConnectionService` и работает через `connect`, `list` и `disconnect`.
SQL-редактор получает `SqlService`, редактор схемы — `SchemaService`. Оба сервиса
используют открытые сессии общего реестра и регистрируют очистку своих данных
при отключении. При завершении приложения `SessionRegistry.close()` закрывает
все оставшиеся подключения.

`CsvService` проверяет область экспорта, ограничивает размер чтения и закрывает источник.
`ChangeValidator` возвращает несколько ошибок с путями; он также применён перед
вызовом адаптера. Сервисы синхронны: UI вызывает их в фоновых задачах.

## Регистрация и идентификаторы

При запуске `SessionRegistry` получает коллекцию `AdapterProvider`.
`SchemaService` получает тот же реестр и `TextFilePort` для сохранения DDL.
Повторяющиеся AdapterId отклоняются. Settings.adapter выбирает провайдер;
ports() может вернуть отдельный комплект портов на подключение. Комплект
закрепляется за сессией, поэтому bootstrap не маршрутизирует сценарии.
Провайдер предоставляет правила сравнения имён: core не меняет регистр.

Единственный владелец генерации SessionId — ConnectionPort.connect: новый UUID
на каждое открытие, без повторного использования даже после закрытия. Core хранит
множество ранее выданных ID и отвергает коллизии. При нарушении этого контракта
адаптер отвечает за устранение утечки своего ошибочно открытого подключения:
core не вызывает disconnect с дублированным ID, чтобы не закрыть исходную сессию.
ObjectId включает SessionId и непрозрачное локальное значение адаптера;
ссылки на таблицы FK по квалифицированным именам проверяет адаптер.
ResultId и ChangePlanId генерирует адаптер как уникальные UUID.
OperationId UI получает через newOperationId() **до** запуска execute/explain.
Повторное использование операции отвергается, даже после её завершения. Отмена с
зарезервированным ID запоминается, в том числе до вызова execute/explain и во время
проверки возможностей адаптера.

## Создание таблицы и применение

UI создаёт CreateTable с Table/Column/Constraint. Request-модели являются
типизированными черновиками: имена и SQL-выражения могут быть пустыми, отдельные
обязательные поля — null. Коллекции должны быть не null и не содержать null;
отсутствующие необязательные поля задаются Optional.empty(). Это контракт
построения DTO; нарушение структуры Java-объекта — ошибка программирования UI.
Вложенные модели не утверждают своей корректности при конструировании:
корректность устанавливает валидатор и затем адаптер. Снимки приходят от адаптера,
а не из формы. Коллекции копируются, бинарные значения копируются в обе стороны.

prepareChange проверяет черновик, принадлежность ID, capabilities, получает
согласованный Snapshot и проверяет ссылки ограничений на локальные колонки.
Для изменения существующего объекта проверяется его вид и флаг editable.
Проверки имён, данных, FK и выражений выполняет адаптер. Подготовка возвращает
Preparation: при ошибках формы plan пуст, problems содержит все найденные ошибки.
Адаптер может вернуть неприменимый Plan с объяснениями и SQL для просмотра.

Plan — неизменяемое описание; Prepared содержит его и закрытый от UI
ExecutionRecipe. Рецепт может описывать копирование, настройки соединения,
восстановление объектов и проверки; он не содержит живых ресурсов или JDBC.
Это минимальное расширение порта для исполнения именно подготовленного плана.
Core проверяет совпадение сессии, намерения и версии контекста.

UI подтверждает ChangePlanId. applyChange принимает **ID**, находит сохранённый
Prepared и передаёт адаптеру тот же объект. Подложить новый Plan через публичный
API нельзя. План другой сессии отклоняется. Один ID допускает только одну попытку;
конкурентные отправки сериализуются, вторая получает ALREADY_APPLIED.
Попытка потребляется до внешнего вызова, включая ошибки связи. Неприменимый
план не отправляется адаптеру. CONFLICT требует нового preview; переподготовки,
повтора или применения нового SQL по старому подтверждению нет.

## Обязательные гарантии адаптера

- Согласованный snapshot с происхождением, диалектом и непрозрачным stateToken.
- Подготовка не меняет БД и не удерживает блокировки на время просмотра UI.
- Рецепт неизменяем, свободен от ресурсов и принадлежит соответствующей сессии.
- При apply под защитой движка повторно проверяются состояние схемы **и данные**.
  Несовпадение даёт ApplyStatus.CONFLICT без изменения БД; исход и границы отката
  сообщаются фактически. Изменение статуса в памяти core не откатывает БД.
- Миграции, пересоздание таблицы, FK-настройки и диалектные SQL находятся в адаптере.
- Отмена потокобезопасна и работает одновременно с execute/explain и догрузкой.
  UI передаёт ID исходного запроса. Core назначает каждой догрузке отдельный ID
  для порта. Адаптер поддерживает отменяемую догрузку через перегрузку fetchRows
  с OperationId. Адаптер согласует cancel с запуском движка и возвращается без
  ожидания завершения операции.
- Таймаут и транзакционная политика запроса исполняются адаптером.
- SINGLE_STATEMENT: движок/надёжный анализ адаптера отвергает несколько команд
  целиком **до побочных эффектов**. split(";") недопустим. Core не классифицирует
  SQL, не добавляет LIMIT/COUNT, не отбрасывает результаты и не повторяет SQL.
- disconnect освобождает все результаты и прочие ресурсы сессии. Каждая успешная
  операция открытия/исполнения передаёт core только валидные метаданные и ID;
  при собственной ошибке до передачи адаптер сам освобождает ресурсы.
- Все ожидаемые ошибки адаптера переводятся в CoreException с безопасной
  диагностикой. JDBC-исключения и соединения не пересекают границу порта.

## Конкурентность и закрытие

У каждой сессии свой lock: основные вызовы последовательны внутри сессии;
разные сессии работают параллельно. Общий монитор используется для регистрации
и ожидания открытий. cancel обходит lock сессии, поэтому доступен во время SQL,
EXPLAIN и догрузки строк. Итог операции сообщает движок.

disconnect сначала помечает сессию closing, запрещает новые операции, запрашивает
отмену активного SQL, EXPLAIN или догрузки и ожидает текущий вызов, затем вызывает
порт disconnect. Долгий вызов, игнорирующий cancel/таймаут, может задержать закрытие;
core не уничтожает потоки и не заявляет о несуществующем откате. Отдельной отмены
миграций MVP не предоставляет. При неуспешном disconnect сессия остаётся closing;
повторное закрытие снова пытается освободить ресурсы, операции не возобновляются.
После успешного disconnect повтор безопасен. close() прекращает приём операций
и закрывает зарегистрированные сессии. Затем дожидается уже начатых открытий и
закрывает те подключения, которые открылись в ходе завершения приложения.
Ошибки очистки собираются, оставшиеся сессии всё равно закрываются. Неуспешное
закрытие можно повторить.
Неизвестный SessionId при disconnect — UNKNOWN_SESSION.

## SQL, планы, ресурсы

Execution различает команду и открытый результат; Statistics.receivedRows,
affectedRows и totalRows независимы, последние два могут отсутствовать.
Batch.complete означает конец выдачи, но closeResult всё равно обязателен.
NULL представлен NullValue, числа — BigDecimal, бинарные данные — защитной копией,
временные значения — типами java.time. Параметры позиционные, позиции начинаются с 1.

QueryPlan сохраняет лес узлов, UNKNOWN/OTHER, исходное имя и описание, атрибуты,
rawOutput и rawFormat. Отсутствующие метрики остаются отсутствующими.
Mode.ESTIMATED не выполняет запрос; ANALYZE требует явного выбора и capability.
Core не разбирает EXPLAIN.

Обычный результат принадлежит SqlService до closeResult/disconnect.
remainingRows передаёт курсор в исключительное владение RowSource; UI больше не
может его читать/закрывать. Источник возвращает только оставшиеся строки, без
первой порции и прочитанных UI строк. Его надо закрыть либо передать CsvService.
Закрытие источника после закрытия сессии безопасно. При ошибке очистки источника
close можно повторить. После такой ошибки курсор доступен только для освобождения,
в том числе через closeResult по исходному ID. Параллельные чтения через UI и
экспорт отклоняются, повторное выполнение SQL не происходит.

## Экспорт

DDL: сервис получает snapshot и передаёт его DdlExportPort этого адаптера.
Адаптер обязан обслуживать source dialect из DatabaseInfo/Snapshot.
DdlOptions выбирает всю схему либо непустой набор ID; INCLUDE включает зависимости,
SELECTED_ONLY оставляет выбранные объекты. Генератор определяет порядок,
предупреждает о неполных зависимостях/отсутствующих определениях и сообщает
independentlyRestorable. Core не достраивает SQL догадками. saveDdl передаёт
полученный текст TextFilePort **без изменения**; предупреждения возвращаются UI.
Для сохранения уже показанного preview UI вызывает saveDdlPreview;
saveDdl сам получает свежий preview и возвращает его.

CSV: CsvService.export немедленно принимает владение переданным источником,
закрывает его при успехе, ошибке, отмене и ошибке параметров. Порт не закрывает
источник и читает порциями; сервис ограничивает размер запроса и проверяет ответ.
FULL_SOURCE — гарантированный владельцем свежий полный источник;
SELECTED_BATCH — явно выбранная порция (фабрика CsvService.selectedBatch);
REMAINING — оставшийся курсор. Несовпадение запрошенной области и source.scope
отклоняется. Полный экспорт уже потреблённого результата требует отдельного
явного выполнения SQL пользователем либо заранее сохранённого полного источника.

CsvOptions задаёт заголовки, разделитель, Charset, nullText, MINIMAL/ALL и размер
порции. IO использует двойные кавычки, удваивает кавычку внутри поля; MINIMAL
кавычит поля с разделителем, кавычкой, CR/LF, ALL — каждое поле. Форматирование
типов (числа без локали, ISO-время, согласованное кодирование бинарных данных)
должно быть документировано IO. Порт проверяет Cancellation в процессе записи;
сервис дополнительно проверяет его перед чтением каждой порции и после записи.
Отмена/ошибка может оставить частичный файл: атомарная запись — ответственность IO.

## Ошибки и ограничения MVP

Ошибки формы — Problem(code, severity, path, message, details). Имена кодов
required/empty/duplicate/unknown_column/multiple_primary_keys/foreign_key_arity/
index_term стабильны. Ошибки сценария — CoreException с Code; диагностические
vendorCode/sqlState/safeMessage сохраняются без замены. Код включает INVALID_INPUT,
UNKNOWN_ADAPTER/SESSION, WRONG_SESSION, NOT_FOUND, UNSUPPORTED, CONFLICT,
CONSTRAINT, CONNECTION, BUSY_TIMEOUT, CANCELLED, SQL, IO, INTERNAL,
ALREADY_APPLIED, OUTCOME_UNKNOWN. Непредвиденные RuntimeException на основной
границе адаптера превращаются в INTERNAL без небезопасного текста исключения.
Settings.toString скрывает все свойства и секреты; адаптер обязан редактировать
свои сообщения и логи. SQL и значения параметров автоматически не журналируются.

Нет UI, JDBC, конкретного SQL/EXPLAIN, файловой записи, ручных транзакций,
парсера, повторов и поддержки скриптов. Идентификаторы хранятся в памяти экземпляра
сервиса для предотвращения повторов. Рецепты использованных планов, метаданные
закрытых курсоров и данные закрытых сессий освобождаются. История идентификаторов
действует до завершения приложения.

Флаг Definition.editable=false запрещает изменение определения объекта.
Допустимость создания отдельного индекса на такой таблице определяет адаптер.
Исходное определение используется для просмотра и экспорта.
